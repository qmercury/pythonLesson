## 이론 (20분)

딕셔너리는 `이름: 값`으로 기록을 관리한다. 탐색 전체 기록의 길이에서 중복을 제거한 집합 길이를 빼면 재방문 수를 알 수 있다. 평균은 값의 합계를 기록 개수로 나눈 것이다. 청소 면적과 이동 횟수는 다른 성능 지표이므로 하나만 보고 최고 알고리즘을 결정하면 안 된다.

## 짧은 예시

`record = {"name": "A", "seconds": 38}`의 값을 `record["seconds"]`로 읽는다. `len(route) - len(set(route))`로 중복 방문을 계산한다.

## 보충 이론: 기록이 의미 있는 데이터가 되려면

### 딕셔너리로 하나의 주행을 표현

```python
record = {
    'name': 'team A',
    'route': [(0, 4), (1, 4), (1, 4)],
    'seconds': 45
}
```

주행에서 다음 지표를 구분한다.

| 지표 | 계산 | 의미 |
|---|---|---|
| 실제 이동 횟수 | `len(route) - 1` | 한 칸 이동의 총 횟수 |
| 서로 다른 방문 위치 | `len(set(route))` | 중복을 제외한 방문 칸 |
| 재방문 횟수 | `len(route) - len(set(route))` | 이미 방문한 칸 재진입 |
| 청소율 | `(서로 다른 청소한 칸 / 전체 바닥 칸) × 100` | 얼마나 넓게 청소했는가 |

이 지표는 각 주행이 실제로 인접한 좌표로 구성됐고, 시작점이 한 번 기록됐다는 전제에서 사용한다.

### 데이터 분석 활동

세 팀을 단순히 '최고의 로봇'으로 순위 매기지 말고, 먼저 **평가 기준**을 정의하게 한다. 같은 청소율이라면 시간이 짧은 로봇이 유리할 수 있지만, 청소율이 크게 차이 나면 주행 시간만으로 비교할 수 없다.

**도전:** 최고 청소율 → 최소 이동 횟수 → 최소 소요시간 순서로 비교하는 기준을 설계한다.
