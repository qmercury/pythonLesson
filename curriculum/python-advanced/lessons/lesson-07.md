## 이론 (20분)

GUI는 `while True`에 긴 연산이나 `time.sleep()`을 넣으면 창이 멈출 수 있다. `root.after(밀리초, 함수)`는 일정 시간 뒤 함수를 다시 호출하므로 화면을 유지하면서 자동 실행할 수 있다. `running` 같은 상태 변수로 시작·일시정지·종료를 구분한다.

## 짧은 예시

`root.after(250, tick)`은 0.25초 뒤 `tick()`을 예약한다. 콜백 안에서 상태를 변경한 뒤 필요한 경우에만 다시 예약한다.

## 보충 이론: GUI를 멈추지 않는 반복

Turtle이나 콘솔에서 사용하던 `while True`를 Tkinter 버튼 콜백에 넣으면 이벤트 처리가 막힐 수 있다. 그래서 **한 번에 한 동작만 수행하고 다음 동작을 예약**한다.

```python
def tick():
    if running:
        print('한 단계 실행')
        root.after(250, tick)
```

여기서 `root.after(250, tick)`은 `tick()`을 **나중에 호출 예약**하는 것이다. `tick()`을 지금 바로 실행하는 `tick()`과 다르다.

### 상태 머신 개념

- `stopped`: 초기 상태
- `running`: 자동 실행 중
- `paused`: 일시정지
- `finished`: 작업 종료

여러 버튼으로 같은 작업을 중복 예약하면 두 번씩 빨라지는 문제가 생긴다. 시작 버튼을 연달아 눌러 보고 `running` 검사로 이를 방지하도록 한다.

### 교사 시연

`time.sleep(2)`를 버튼 콜백에 넣었을 때 창이 반응하지 않는 상황과 `after()`로 처리했을 때를 비교한다. 다만 학생 코드에는 무한루프 실험을 그대로 남기지 않는다.

**도전:** 속도를 초당 1칸, 2칸, 4칸으로 변경할 수 있게 한다.
