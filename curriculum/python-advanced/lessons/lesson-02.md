## 이론 (20분)

깊이 우선 탐색(DFS)은 한 방향으로 계속 이동하다가 갈 곳이 없으면 이전 위치로 돌아간다. 스택의 마지막 항목은 현재 탐색 위치다. `append()`는 전진, `pop()`은 탐색 경로에서 한 단계 복귀에 대응한다. 단, 실제 주행 궤적에는 돌아온 좌표를 별도로 기록해야 한다.

## 짧은 예시

`stack = [start]`에서 출발한다. 갈 수 있는 미방문 칸을 찾으면 `append`; 더 이상 없다면 `pop`. 실제 이동 기록 `route`에는 뒤로 이동한 좌표도 넣는다.

## 보충 이론: 두 종류의 경로 기록

DFS에서는 다음 세 가지를 구분한다.

| 이름 | 역할 | 사용하는 연산 |
|---|---|---|
| `visited` | 처음 방문한 위치 기억 | `add`, `in` |
| `stack` | 현재 들어가 있는 탐색 경로 | `append`, `pop` |
| `route` | 실제로 이동한 모든 위치 | `append` |

예를 들어 A→B→C로 들어갔다가 C가 막다른 길이라서 B로 돌아왔다면, `stack`에서는 C를 `pop()`하지만 실제 주행 기록은 `[A, B, C, B]`가 된다.

스택에서 제거된 좌표가 실제로 자동으로 지워지는 것은 아니다. 로봇이 돌아갈 때에도 **이전 칸까지 실제로 한 번 이동**한다는 사실을 확인시킨다.

### 지도 예시를 이용한 탐색 규칙

```python
current = stack[-1]
choices = [p for p in neighbors(room, current) if p not in visited]
```

여기서 `choices`가 있다면 새로운 칸으로 이동하고, 없다면 돌아간다. DFS 탐색이 끝날 때 스택은 비고, 출발점을 포함한 연결된 모든 칸을 방문한다. 미로에 막힌 길이 많을수록 `route` 길이와 `visited` 크기의 차이가 커진다.

**확인 질문:** `route`의 요소를 `pop()`으로 지워 버리면 '총 이동 횟수'를 정확하게 계산할 수 있을까?
