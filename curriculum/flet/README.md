# Python 크리에이티브 코딩 3 — Flet (12차시 설계 초안)

> Thonny에서 Python 앱을 만들고, PC·웹·스마트폰에서 동작하는 사용자 인터페이스를 경험한다.

**문서 상태: 초안.** Turtle/Tkinter 각 12차시를 바탕으로 한 후속 교육과정으로 제안하며, 개강 전에 Flet 버전과 각 플랫폼 실행 환경을 검증한다.

- 대상: SPIKE Prime Python 기초 및 GUI 이벤트 개념 학습자(권장: Tkinter 기초 경험)
- 시간: 회당 90분
- 도구: Thonny(코드 편집) + 지원 Python(공식 문서 기준 3.10 이상) + Flet
- 산출물: 휴대폰에서 테스트 가능한 Python 앱(점수판/퀴즈/할 일/기록 관리 중 선택)
- 목표: UI 컴포넌트, 이벤트, 화면 구성, 데이터 모델, 크로스플랫폼 테스트와 배포의 차이 이해

## 왜 Flet을 배우는가?

- Tkinter: PC용 기본 GUI를 만드는 데 적합하며 설치가 간단하다.
- Flet: Python으로 데스크톱·웹·모바일용 인터페이스를 작성할 수 있다.
- **Tkinter 소스의 자동 모바일 변환이 아니다.** 변수·함수·계산 로직은 재사용하고 UI는 Flet 컨트롤로 새로 구성한다.
- Thonny는 **편집기·실행 환경**이고 휴대폰 실행과 빌드는 Flet이 담당한다.

## 차시별 미션

### 01 — 첫 번째 Flet 앱
- **기본** 제목과 자기소개 글자 표시 / **응용** 글자 크기와 색상 변경 / **도전** 서로 다른 3개 소개 항목.
- 확인: page와 Tkinter의 root가 모두 앱의 시작 화면을 나타내지만 사용하는 API는 다름.

### 02 — 버튼과 이벤트
- **기본** +1 버튼 / **응용** -1·초기화 / **도전** 두 팀 점수판.
- 확인: on_click 이벤트가 Python 함수를 호출한다.

### 03 — 사용자 입력
- **기본** 이름을 입력받아 인사말 표시 / **응용** 빈 값 검사 / **도전** 두 개 이상의 입력 조합.
- 확인: 문자열 입력과 숫자 변환의 차이.

### 04 — 화면 구성·디자인
- **기본** 세로 배치 / **응용** 가로 버튼 정렬 / **도전** 넓고 좁은 화면에서 적절한 배치.
- 확인: 컴포넌트 계층 구조를 설명할 수 있다.

### 05 — 미니 계산기
- **기본** 덧셈 / **응용** 사칙연산 / **도전** 잘못된 입력·0 나누기 오류 안내.
- 확인: UI 코드와 계산 함수를 구분한다.

### 06 — 퀴즈 게임
- **기본** 한 문제 맞히기 / **응용** 점수·정답 피드백 / **도전** 여러 문제와 최종 결과.
- 확인: 화면 상태가 사용자 선택에 따라 변한다.

### 07 — 여러 화면
- **기본** 시작 화면과 게임 화면 / **응용** 뒤로 가기 / **도전** 화면 사이 공통 상태 유지.
- 확인: 단일 창 안에 여러 화면을 구성할 수 있다.

### 08 — 할 일 목록
- **기본** 항목 추가 / **응용** 완료·삭제 / **도전** 남은 항목 개수와 빈 목록 안내.
- 확인: 화면에 나타나는 항목은 리스트 데이터에서 나온다.

### 09 — 기록 저장
- **기본** 현재 실행 중 기록 유지 / **응용** 데이터 파일로 저장·읽기 / **도전** 저장 실패 상황 안내.
- 확인: PC의 파일 경로와 모바일 앱 내부 저장소는 달라질 수 있음을 이해한다. 모바일 환경에서는 지원되는 저장 방식으로 교체한다.

### 10 — 스마트폰 시험
- **기본** PC와 휴대폰을 같은 네트워크에 연결 / **응용** 모바일 화면에서 버튼·입력 테스트 / **도전** 작은 화면의 레이아웃 개선.
- 확인: 개발용 Flet 앱에서 QR로 **미리보기** 하는 것과 앱 설치 파일 배포는 다르다.

### 11 — 자유 프로젝트
- 선택: 퀴즈, 로봇경기 점수판, 할 일 앱, 기록 관리.
- 필수: 화면 2개 이상 또는 핵심 기능 3개, 사용자 입력 1개, 오류 안내 1개.
- 결과물: 친구가 사용할 수 있는 테스트 버전.

### 12 — 마무리와 배포 개념
- 친구의 휴대폰 또는 테스트 기기에서 실제 사용 테스트(가능한 경우).
- 개발 서버 미리보기 / 웹 배포 / APK·AAB / iOS 빌드의 차이 설명.
- 발표: 앱의 사용자, 핵심 기능, 오류 수정, 다음 버전 아이디어.
- 앱 스토어 등록이나 서명 절차는 학생 필수 수행 과제가 아닌 교사 심화·운영 과제로 둔다.

## 예시: 첫 Flet 앱

~~~python
import flet as ft

def main(page: ft.Page):
    page.title = "나의 첫 Flet 앱"
    page.add(
        ft.Text("안녕하세요!", size=28),
        ft.Text("Python으로 만든 프로그램입니다.")
    )

ft.run(main)
~~~

실행은 Flet이 설치된 **동일한 Python 환경**에서 Thonny의 F5 또는 OS 터미널의 flet run을 사용한다. Thonny가 다른 인터프리터를 선택했으면 패키지가 보이지 않을 수 있다.

## 휴대폰 테스트 및 배포에 대한 주의

1. Flet의 스마트폰 테스트 앱 설치 후, PC·휴대폰을 같은 Wi-Fi/로컬 네트워크에 연결한다.
2. 개발용 터미널에서 flet run --android 또는 flet run --ios [스크립트]를 실행해 QR코드로 미리 본다.
3. 모바일 테스트는 **독립 설치 앱의 생성이 아님**. 교실에서는 교사가 네트워크·기기 연결을 지원한다.
4. Android 설치 패키지는 별도 빌드(예: flet build apk), iOS 배포에는 macOS 기반 빌드와 서명/개발자 조건이 필요할 수 있다.
5. Flet의 API와 빌드 절차는 버전별로 변화하므로 예제 작성 시 공식 문서와 사용 버전을 고정해 검증한다.
6. 웹앱 공개 시 학생의 실명·개인정보를 올리지 않고, 인증과 서버 보안이 필요한 기능은 별도 설계한다.
