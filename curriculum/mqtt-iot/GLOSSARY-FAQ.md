# MQTT·IoT 용어 해설과 교사 Q&A

이 자료는 학생과 함께 화면에 띄우거나 프린트할 수 있는 **짧은 설명 카드**다.

## 설명 카드 10장

| 용어 | 쉬운 뜻 | 예시 |
|---|---|---|
| 네트워크 | 컴퓨터가 서로 통신할 수 있도록 연결된 환경 | 같은 Wi-Fi |
| IP 주소 | 네트워크의 컴퓨터 주소 | 192.168.0.10 (예시) |
| 브로커 | 메시지를 받아 구독자에게 전하는 서버 | 교실 방송실 |
| 발행자(Publisher) | 메시지를 보내는 프로그램 | 학생 A의 조종기 |
| 구독자(Subscriber) | 메시지를 받기로 신청한 프로그램 | 학생 B의 수신기 |
| 토픽(Topic) | 메시지를 구분하는 채널 이름 | class01/robot01/cmd |
| 페이로드(Payload) | 메시지의 실제 내용 | forward |
| 콜백(Callback) | 메시지 도착 등 사건이 생겼을 때 자동 실행되는 함수 | on_message |
| JSON | 이름과 값으로 묶인 자료 형식 | {"action":"forward"} |
| 직렬통신(Serial) | 데이터를 차례대로 보내는 통신 방식 | 컴퓨터 ↔ EV3 Bluetooth |

## 문제 카드: 말로 답하기

1. 학생 A는 `robot01/cmd`에 메시지를 보냈습니다. B가 `robot02/cmd`만 구독한다면? → **B는 받지 못함**.
2. 브로커에 연결하지 않아도 다른 학생의 메시지를 받아볼 수 있을까요? → **일반적인 MQTT 방식에서는 불가**.
3. `publish`가 성공하면 EV3도 무조건 움직일까요? → **아니요**. 메시지 배달과 장치 실행은 다릅니다.
4. 인터넷이 끊기면 교실 IoT는 반드시 중단될까요? → **아니요**. 로컬 MQTT 브로커와 같은 LAN이 살아 있으면 동작할 수 있습니다.
5. `Wi-Fi`와 `MQTT`의 차이는? → **Wi-Fi는 네트워크 연결, MQTT는 메시지 통신 규칙**.
6. 누군가 같은 명령을 두 번 보내면? → **두 번 실행될 수도 있음**. 메시지 ID 확인으로 중복 실행을 예방.
7. 명령을 받은 뒤 결과를 돌려주려면? → **status 토픽에 결과를 발행**.
8. MQTT 브로커 비밀번호를 GitHub에 올려도 될까요? → **안 됩니다**.

## 헷갈리는 것 비교

| A | B | 차이 |
|---|---|---|
| 연결 성공 | 메시지 전달 성공 | 연결만으로 송수신이 보장되지 않음 |
| 메시지 전달 | 모터 실행 | 수신 후 명령 검사·기기 연결이 필요 |
| MQTT | Bluetooth 직렬통신 | PC 간 네트워크 메시지 vs PC-EV3 통신 |
| `publish` | `subscribe` | 보내기 vs 듣기로 신청 |
| `loop_start()` | `mainloop()` | MQTT 네트워크 처리 vs Tkinter UI 이벤트 처리 |
| `queue.Queue()` | MQTT Broker | PC 프로그램 내부 메시지 전달 vs 네트워크 중계 서버 |
| QoS 1 | 한 번만 모터 실행 | QoS 1은 중복 메시지가 가능, 물리 실행은 별도로 보호 |
| `retained=True` | `retained=False` | 브로커에 마지막 메시지 보관 여부 |

## 칠판 연습

- 토픽을 `robottagram/class01/robot01/cmd`로 만들고, 학생 3명이 각각 어떤 토픽을 구독할지 정한다.
- 메시지 `{"action": "left"}`를 받고 어떤 프로그램이 실행할지 논의한다.
- 수신 확인 `{"state":"simulated","detail":"left"}`와 실제 로봇 실행 완료의 차이를 설명한다.

교사용 더 자세한 설명은 [교사용 입문 교재](TEACHER-HANDBOOK.md).
