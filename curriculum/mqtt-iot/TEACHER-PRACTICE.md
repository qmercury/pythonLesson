# 교사 사전 학습 및 수업 전 점검표

처음 MQTT를 접하는 교사를 위한 **직접 실행 중심 준비 가이드**다. 학생 앞에서 시연하기 전에 아래 항목을 교사 PC에서 한 번씩 해 본다.

## 1단계 — 개념을 자기 말로 설명할 수 있는가?

- [ ] Publisher/Subscriber/Broker를 학교 방송실 비유로 설명한다.
- [ ] Topic과 Payload의 차이를 예를 들어 설명한다.
- [ ] 학생 A와 B가 서로의 PC IP 대신 **브로커 주소**로 접속하는 이유를 설명한다.
- [ ] QoS 1의 **중복 전달** 가능성을 알고 있다.
- [ ] 실제 로봇은 MQTT 메시지 수신과 별개로 자동 정지 안전장치가 필요함을 알고 있다.

## 2단계 — 교사 준비물

- [ ] Thonny가 실행되는 PC 2대 또는 동일 PC의 서로 다른 실행 프로세스 2개
- [ ] 같은 로컬 네트워크에 있는 **MQTT 브로커 1개** (Raspberry Pi 4 또는 별도 PC)
- [ ] 브로커 IP 확인, 포트 1883 접근 허용 여부 확인 (교실 LAN 한정)
- [ ] MQTT 접속 계정/비밀번호 (교사용 별도 보관, GitHub에 업로드하지 않음)
- [ ] Thonny에 `paho-mqtt` 2.x 설치
- [ ] [콘솔 수신](../../examples/mqtt-iot/step01_subscriber.py), [콘솔 송신](../../examples/mqtt-iot/step02_publisher.py), [콘솔 채팅](../../examples/mqtt-iot/step03_console_chat.py) 준비
- [ ] [Tkinter 채팅](../../examples/mqtt-iot/mqtt_chat.py), [조종기](../../examples/mqtt-iot/mqtt_controller.py), [가상 로봇](../../examples/mqtt-iot/mqtt_gateway_simulator.py), `protocol.py` 복사

## 3단계 — 브로커가 무엇인지 직접 느껴 보기

**먼저 그림:** 학생 A → 브로커 → 학생 B. Wi-Fi 공유기가 있다고 브로커가 자동 설치되는 것은 아니다.

교실에 Mosquitto 서버가 구성된 상태라면 (아래 명령은 **교사 PC에서**, 실제 IP로 수정):

```bash
# 브로커의 특정 메시지를 듣는 사람(구독자)
mosquitto_sub -h 192.168.0.10 -p 1883 -u classroom -P '비밀번호' -t 'robottagram/class01/chat' -v

# 다른 터미널에서 메시지를 보내는 사람(발행자)
mosquitto_pub -h 192.168.0.10 -p 1883 -u classroom -P '비밀번호' -t 'robottagram/class01/chat' -m '안녕하세요!'
```

`192.168.0.10`은 **예시 IP**다. 공유기의 DHCP/서버 IP를 확인한다. `-P` 방식은 비밀번호가 셸 이력에 남을 수 있으므로 **수업용 임시 계정**에서만 사용하고, 운영 중에는 보다 안전한 인증/비밀 관리 방법을 택한다.

**성공하면:** 구독 터미널에 메시지가 즉시 나타난다.

**실험:** `class02` 채널만 구독한 터미널에서는 `class01` 메시지가 안 나타나는지 확인한다.

## 4단계 — 2차시 콘솔 단방향 통신

1. 학생 B(수신자) PC에서 `step01_subscriber.py` 실행, 연결 완료/구독 표시 확인.
2. 학생 A(송신자) PC에서 `step02_publisher.py` 실행.
3. 학생 B의 Thonny Shell에 실제 메시지가 출력되는지 확인.
4. `PAYLOAD`를 변경해 다시 송신하고, 서로 다른 `ROOM`이면 메시지가 안 오는지 관찰.

## 5단계 — 3차시 콘솔 양방향 채팅

1. 두 PC에서 `step03_console_chat.py`를 각각 실행.
2. `나의 별명`을 입력하고, `보낼 메시지:`에 문장을 입력해 Enter.
3. A/B 양쪽 콘솔에 `[받음]`이 나타나는지 확인.
4. 자신이 보낸 메시지도 표시되는 이유를 '둘 다 구독자'로 설명.

## 6단계 — 4차시 Tkinter 채팅

1. 양쪽 PC에서 `MQTT_HOST`, `MQTT_USER`, `MQTT_PASSWORD`, `MQTT_ROOM`을 동일하게 구성.
2. `mqtt_chat.py`를 두 PC에서 각각 실행.
3. 두 창에 **MQTT 연결됨** 표시 확인.
4. PC A의 메시지가 PC B에 나타나는지 확인하고 역할 반대도 시험.
5. PC B를 종료해도 A의 앱이 즉시 망가지지 않는 이유를 설명한다(브로커에 계속 연결되어 있음).
6. 다음 메시지부터는 A의 구독 토픽을 바꿔 전달되지 않는 것을 확인한다.

**Thonny 주의:** 터미널의 `export MQTT_HOST=...`가 이미 열려 있는 Thonny 프로세스에는 적용되지 않을 수 있다. 준비된 실행 스크립트/환경변수 설정으로 Thonny에서 직접 확인한다.

## 7단계 — 5~7차시 명령 → 가상 로봇 → 상태 회신

1. B 컴퓨터에서 `mqtt_gateway_simulator.py` 실행.
2. A 컴퓨터에서 `mqtt_controller.py` 실행.
3. 양쪽 room과 robot이 **완전히 동일**한지 확인.
4. A에서 전진 클릭 → B Canvas의 파란 가상 로봇이 이동하는지 확인.
5. B에서 처리한 상태가 A의 화면으로 돌아오는지 확인.
6. B를 끈 뒤 A가 계속 메시지를 보내면 실제로 실행되는 로봇은 없음을 확인한다.
7. **이 단계에서는 실제 EV3 모터를 연결하지 않는다.**

## 8단계 — 오류 대응 연습

| 상황 | 교사가 먼저 확인할 항목 |
|---|---|
| 양쪽 모두 MQTT 연결 불가 | 브로커 서비스 실행, IP, 방화벽, 인증 실패 |
| A만 연결되고 B는 실패 | B 네트워크/환경 변수/사용자 권한 |
| 연결은 됐는데 채팅 불가 | 토픽/room이 같나? Subscribe 했나? |
| 메시지는 전송했는데 Canvas 변화 없음 | robot ID가 같은가? 수신기 실행 중인가? 명령이 만료됐나? |
| Python 모듈을 못 찾음 | Thonny 선택 인터프리터에 `paho-mqtt` 설치했나? |
| 버튼 누르니 화면이 멈춤 | 네트워크 연결을 Tkinter 메인 스레드에서 동기적으로 기다리지는 않나? |
| 연결 끊긴 후 로봇이 계속 움직임 | **실물 로봇 테스트 중단**. 로봇 내부 watchdog이 먼저 필요 |
