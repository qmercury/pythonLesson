# 07차시 — 결과를 돌려주는 양방향 통신

> 학생용 실습지 + 교사 안내 / 90분 / **교실 로컬 MQTT 브로커(필요 차시) 사용**

## 오늘의 목표
cmd 토픽과 status 토픽을 구별하고 왕복 통신을 시험한다.

## 수업 시작 — 교사가 묻기 (0~10분)
전진 버튼을 눌렀는데 로봇이 안 움직였다면 조종하는 사람은 어떻게 알 수 있을까요?

## 꼭 배울 개념 (10~25분)
A는 `cmd`에 명령을 발행하고 `status`를 구독한다. B는 `cmd`를 구독하고 처리 결과를 `status`로 발행한다. 발행과 구독은 각 컴퓨터가 동시에 할 수 있다.

### 교사가 직접 보여 주는 활동
B 시뮬레이터를 연결한 뒤 A 조종기에서 명령 버튼을 누른다. 수신기에서 `simulated` 상태를 발행하고 A 화면에 표시되는 것을 확인한다.

## 학생 실습 (25~55분)
**기본 미션:** 명령→처리→상태 회신의 세 화살표를 그린다.

## 더 해보기 (55~75분)
**응용:** B를 종료한 뒤 A 조종기 화면의 마지막 상태와 실제 실행 여부가 어떻게 달라지는지 기록한다.

**도전:** `ready`, `simulated`, `rejected` 상태별 사용자 안내 문구를 설계한다.

## 확인하고 기록하기 (75~90분)
- 내가 만든 화면이나 결과를 옆 학생에게 보여 준다.
- **생각 질문:** 같은 컴퓨터가 Publisher이면서 Subscriber일 수 있나요?
- **성공 기준:** 명령과 상태의 토픽 이름이 다른 이유를 설명하면 성취.
- 포트폴리오 2문장: "오늘 배운 통신 개념은 ______ 입니다." / "시험해 본 결과는 ______ 입니다."

## 교사용 지도 팁
- **자주 하는 실수:** 상태 회신도 네트워크 사정에 따라 늦거나 누락될 수 있다. 상태가 없으면 성공으로 가정하지 않는다.
- **설명/정답 포인트:** MQTT 발행 확인과 로봇 실행 결과는 다르므로 반드시 별도 상태 메시지가 필요하다.
- **수업 전 준비와 참고:** [mqtt_controller.py](../../../examples/mqtt-iot/mqtt_controller.py), [mqtt_gateway_simulator.py](../../../examples/mqtt-iot/mqtt_gateway_simulator.py)
- **실물 로봇 주의:** EV3 Legendary 사용자 직렬 송수신 및 자동정지 기능이 검증되기 전에는 실제 모터에 연결하지 않는다.
