# 01차시 — MQTT와 IoT 만나기

> 학생용 실습지 + 교사 안내 / 90분 / **교실 로컬 MQTT 브로커(필요 차시) 사용**

## 오늘의 목표
브로커·발행자·구독자·토픽 네 역할을 자기 말로 설명한다.

## 수업 시작 — 교사가 묻기 (0~10분)
'학생 A가 버튼을 누르면 다른 학생의 컴퓨터에 어떻게 알릴까?' 라고 묻는다. 학생 세 명에게 각각 A, 방송실, B 카드를 나누어 준다.

## 꼭 배울 개념 (10~25분)
A가 B에게 직접 이야기하는 대신 브로커에 전달한다. B는 듣고 싶은 토픽을 미리 구독해야 메시지를 받는다. IP는 컴퓨터를 찾아가는 주소, 토픽은 MQTT 안에서 메시지를 구분하는 이름이다.

### 교사가 직접 보여 주는 활동
종이에 `robottagram/class01/chat`을 적고, A의 메시지 '안녕'을 브로커 역할 학생을 거쳐 B에게 전달한다. 다른 토픽을 선택한 C에게는 전달하지 않는다.

## 학생 실습 (25~55분)
**기본 미션:** 발행자·브로커·구독자 역할 카드 3장을 올바른 순서로 놓고, 메시지 전달을 두 번 시연한다.

## 더 해보기 (55~75분)
**응용:** 토픽을 `class01`, `class02`로 바꾸고 누가 어떤 메시지를 받을지 예측한다.

**도전:** 두 개 이상의 로봇이 있을 때 토픽 이름을 제안하고, 서로 메시지가 섞이면 어떤 문제가 생길지 설명한다.

## 확인하고 기록하기 (75~90분)
- 내가 만든 화면이나 결과를 옆 학생에게 보여 준다.
- **생각 질문:** 왜 모든 학생에게 모든 메시지를 보내지 않을까요?
- **성공 기준:** MQTT를 '채널을 구독해 메시지를 주고받는 규칙'이라고 설명하면 성취.
- 포트폴리오 2문장: "오늘 배운 통신 개념은 ______ 입니다." / "시험해 본 결과는 ______ 입니다."

## 교사용 지도 팁
- **자주 하는 실수:** 브로커가 모터를 직접 움직인다는 오해. 브로커는 메시지 '전달'만 하고 실제 동작은 수신 프로그램이 한다.
- **설명/정답 포인트:** 받을 메시지가 없을 때는 구독한 토픽과 발행한 토픽이 일치하는지 먼저 확인한다.
- **수업 전 준비와 참고:** [용어 카드](../GLOSSARY-FAQ.md)
- **실물 로봇 주의:** EV3 Legendary 사용자 직렬 송수신 및 자동정지 기능이 검증되기 전에는 실제 모터에 연결하지 않는다.
