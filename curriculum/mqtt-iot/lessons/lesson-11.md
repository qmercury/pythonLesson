# 11차시 — 팀별 IoT 통합 프로젝트

> 학생용 실습지 + 교사 안내 / 90분 / **장비별 검증 상태 확인 후 진행**

## 오늘의 목표
메시지 송신·수신·상태 표시를 한 프로젝트로 통합한다.

## 수업 시작 — 교사가 묻기 (0~10분)
서로 다른 학생이 만든 두 프로그램을 하나의 시스템으로 연결해 보면 어떨까요?

## 꼭 배울 개념 (10~25분)
전체 시스템을 UI, MQTT, 명령 검증, (모의) 로봇, 상태 표시로 나눠 역할을 맡긴다. 작은 모듈로 분리하면 장애가 생겼을 때 원인을 쉽게 찾을 수 있다.

### 교사가 직접 보여 주는 활동
교사는 조종기/시뮬레이터를 띄우고 일부러 robot ID를 다르게 설정한다. 학생에게 원인을 찾게 한 뒤 정상으로 복원한다.

## 학생 실습 (25~55분)
**기본 미션:** 두 PC에서 로봇 조종과 상태 표시를 왕복 1회 구현한다.

## 더 해보기 (55~75분)
**응용:** 팀별 room/robot 구분, 명령 오류 안내, 사용자 메시지 개선 중 두 가지를 추가한다.

**도전:** 센서값이 있는 것처럼 모의 데이터(예: distance=30)를 status로 설계하고 표시할 방법을 정한다.

## 확인하고 기록하기 (75~90분)
- 내가 만든 화면이나 결과를 옆 학생에게 보여 준다.
- **생각 질문:** 로봇이 안 움직일 때 어떤 프로그램부터 확인하면 좋을까요?
- **성공 기준:** 팀별로 메시지 출발점·도착점·상태 회신 경로를 설명하면 성취.
- 포트폴리오 2문장: "오늘 배운 통신 개념은 ______ 입니다." / "시험해 본 결과는 ______ 입니다."

## 교사용 지도 팁
- **자주 하는 실수:** 이 차시는 각 팀 로봇을 무단으로 제어하는 경쟁이 아니다. 브로커 계정·ACL로 접근 범위를 제한한다.
- **설명/정답 포인트:** 상태가 보이지 않으면 (1) 브로커 연결 (2) 토픽 (3) 수신기 (4) 명령 검증 (5) 상태 회신 순으로 좁힌다.
- **수업 전 준비와 참고:** [조종기](../../../examples/mqtt-iot/mqtt_controller.py), [가상 수신기](../../../examples/mqtt-iot/mqtt_gateway_simulator.py)
- **실물 로봇 주의:** EV3 Legendary 사용자 직렬 송수신 및 자동정지 기능이 검증되기 전에는 실제 모터에 연결하지 않는다.
