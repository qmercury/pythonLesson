# 06차시 — 컴퓨터 사이로 가상 로봇 움직이기

> 학생용 실습지 + 교사 안내 / 90분 / **교실 로컬 MQTT 브로커(필요 차시) 사용**

## 오늘의 목표
A의 Tkinter 버튼이 B의 Canvas 로봇을 움직이도록 연결한다.

## 수업 시작 — 교사가 묻기 (0~10분)
이제 메시지의 수신자는 채팅하는 사람이 아니라 화면 속 가상 로봇이라고 소개한다.

## 꼭 배울 개념 (10~25분)
명령을 받은 B 컴퓨터는 `parse_command()`로 검사하고, 유효한 명령만 처리한다. MQTT 통신과 Canvas 좌표 이동은 별개다. B가 가상 모터처럼 움직이는 그림을 표시하는 것이다.

### 교사가 직접 보여 주는 활동
B에서 `mqtt_gateway_simulator.py`, A에서 `mqtt_controller.py`를 켠다. 먼저 두 PC에서 같은 room/robot을 확인한다. A에서 '전진'을 누르면 B의 삼각형이 앞으로 움직인다.

## 학생 실습 (25~55분)
**기본 미션:** 전진 3번, 오른쪽 1번, 전진 2번을 수행하고 최종 위치를 스케치한다.

## 더 해보기 (55~75분)
**응용:** B가 수신한 메시지와 실제 그림 이동을 대응해서 설명한다.

**도전:** 다른 robot ID를 설정한 뒤 왜 로봇이 움직이지 않는지 찾는다.

## 확인하고 기록하기 (75~90분)
- 내가 만든 화면이나 결과를 옆 학생에게 보여 준다.
- **생각 질문:** 명령을 전달한 MQTT 브로커가 화면 속 로봇을 직접 움직였나요?
- **성공 기준:** 한 학생은 조종, 다른 학생은 수신 역할로 1회 성공하고 역할을 교환한다.
- 포트폴리오 2문장: "오늘 배운 통신 개념은 ______ 입니다." / "시험해 본 결과는 ______ 입니다."

## 교사용 지도 팁
- **자주 하는 실수:** 시뮬레이터는 실제 EV3에 연결되지 않는다. 이미지의 20픽셀 이동은 실제 로봇의 20mm 이동이 아니다.
- **설명/정답 포인트:** A에서 '송신 요청'이 보이더라도 B 화면이 움직이지 않으면 브로커·토픽·수신기 실행·명령 만료 시간을 확인한다.
- **수업 전 준비와 참고:** [조종기](../../../examples/mqtt-iot/mqtt_controller.py), [시뮬레이터](../../../examples/mqtt-iot/mqtt_gateway_simulator.py)
- **실물 로봇 주의:** EV3 Legendary 사용자 직렬 송수신 및 자동정지 기능이 검증되기 전에는 실제 모터에 연결하지 않는다.
