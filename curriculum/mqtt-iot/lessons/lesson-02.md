# 02차시 — 첫 MQTT 메시지 보내기

> 학생용 실습지 + 교사 안내 / 90분 / **교실 로컬 MQTT 브로커(필요 차시) 사용**

## 오늘의 목표
publish·토픽·payload를 구분하고 한 번 메시지를 보낸다.

## 수업 시작 — 교사가 묻기 (0~10분)
종이 카드에서 사용했던 '안녕' 메시지를 이제 컴퓨터가 보낼 차례라고 소개한다.

## 꼭 배울 개념 (10~25분)
`publish(topic, payload)`에서 topic은 어느 채널로 보낼지, payload는 실제 내용이다. `1883`은 MQTT 서버에 접속할 때 자주 쓰는 포트 번호이며 서버 주소와 혼동하면 안 된다.

### 교사가 직접 보여 주는 활동
교사는 Mosquitto `mosquitto_sub`로 구독 창을 켜고, 다른 터미널에서 `mosquitto_pub` 명령으로 '안녕하세요'를 발행한다. 교사 사전학습 문서의 인증/브로커 IP를 사용한다.

## 학생 실습 (25~55분)
**기본 미션:** 토픽 `robottagram/class01/chat`에 별명과 한 문장을 전송해 본다.

## 더 해보기 (55~75분)
**응용:** 메시지 내용을 3번 바꾸어 보내고, 구독 창에서 순서를 관찰한다.

**도전:** 구독 토픽을 class02로 바꾼 뒤 class01 메시지가 보이지 않는 이유를 기록한다.

## 확인하고 기록하기 (75~90분)
- 내가 만든 화면이나 결과를 옆 학생에게 보여 준다.
- **생각 질문:** 받는 컴퓨터의 IP를 모르는데 어떻게 메시지를 보낼 수 있을까요?
- **성공 기준:** 학생이 Topic과 Payload 각각을 1문장으로 구분하면 성취.
- 포트폴리오 2문장: "오늘 배운 통신 개념은 ______ 입니다." / "시험해 본 결과는 ______ 입니다."

## 교사용 지도 팁
- **자주 하는 실수:** 인터넷에 공개된 아무 브로커를 실물 로봇 제어에 사용하지 않는다. 브로커 IP와 사용자 인증을 먼저 확인한다.
- **설명/정답 포인트:** 메시지를 받지 못한다면 브로커가 실행 중인지, 발행자/구독자가 같은 서버와 토픽을 사용하는지 확인한다.

- **실물 로봇 주의:** EV3 Legendary 사용자 직렬 송수신 및 자동정지 기능이 검증되기 전에는 실제 모터에 연결하지 않는다.
