# 08차시 — 통신이 끊겨도 안전한 로봇

> 학생용 실습지 + 교사 안내 / 90분 / **교실 로컬 MQTT 브로커(필요 차시) 사용**

## 오늘의 목표
메시지 중복·만료·정지 개념을 이해하고 실물 로봇의 안전 조건을 정리한다.

## 수업 시작 — 교사가 묻기 (0~10분)
'전진' 명령을 받은 뒤 Wi-Fi가 갑자기 끊어졌다면 로봇은 어떻게 해야 할까요?

## 꼭 배울 개념 (10~25분)
QoS 1에는 같은 데이터가 다시 전송될 수 있다. `id`로 중복을 검출하고 `sent_at`으로 너무 오래된 이동 명령을 거부한다. `retain=False`는 오래된 명령을 신규 구독자에게 보관·전달하지 않기 위함이다. 그러나 네트워크 설정만으로 실제 모터 안전이 보장되지 않는다.

### 교사가 직접 보여 주는 활동
`test_mqtt_protocol.py`의 오래된 명령/과도한 속도 테스트를 학생과 함께 읽는다. `python -m unittest discover -s tests -p test_mqtt_protocol.py`로 검사한다.

## 학생 실습 (25~55분)
**기본 미션:** 중복 ID, 오래된 메시지, 잘못된 동작 세 가지를 설명한다.

## 더 해보기 (55~75분)
**응용:** STOP 명령이 도착하지 않아도 자동 정지하도록 EV3 자체 watchdog 규칙을 설계한다.

**도전:** 메시지 수신은 성공했지만 모터가 연결되지 않은 경우 status에 무엇을 기록해야 할지 제안한다.

## 확인하고 기록하기 (75~90분)
- 내가 만든 화면이나 결과를 옆 학생에게 보여 준다.
- **생각 질문:** 메시지 한 번 보내면 한 번만 실행된다고 언제나 믿어도 될까요?
- **성공 기준:** 연결이 끊겨도 자동 정지가 필요한 이유를 설명하면 성취.
- 포트폴리오 2문장: "오늘 배운 통신 개념은 ______ 입니다." / "시험해 본 결과는 ______ 입니다."

## 교사용 지도 팁
- **자주 하는 실수:** STOP 버튼 하나만 만들고 안전하다고 생각하지 않도록 지도한다. 원격 STOP은 도착하지 않을 수 있다.
- **설명/정답 포인트:** 수신기가 허용된 명령만 처리하고, 실제 로봇이 자체 타임아웃으로 멈추도록 설계한다.
- **수업 전 준비와 참고:** [protocol.py](../../../examples/mqtt-iot/protocol.py), [테스트](../../../tests/test_mqtt_protocol.py)
- **실물 로봇 주의:** EV3 Legendary 사용자 직렬 송수신 및 자동정지 기능이 검증되기 전에는 실제 모터에 연결하지 않는다.
